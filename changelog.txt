v5.0.0 (unreleased — this section becomes the 5.0.0 release notes when the
version is first tagged and published; the development commit log lives in
changelog.dev.txt)

Trianglify v5 is a ground-up modernization of the library. See MIGRATING.md
for the v4 → v5 upgrade checklist.

Breaking changes vs v4:
- package is ESM-first ("type": "module") with an exports map: import gets
  ESM, require() gets CJS, script tags keep the UMD bundles in dist/;
  node >= 20 is required (node 18 is end-of-life)
- options are strictly validated: unknown option keys and malformed values
  (including the v4 xColors/yColors: false idiom, empty color arrays, and
  empty or malformed palettes) throw a TypeError instead of being silently
  ignored; width/height/cellSize/shape combinations that would allocate more
  than 1,000,000 points are rejected as an allocation guard — the estimate
  accounts for per-shape geometry (polygon and circle vertices, honeycomb
  row spacing, pentagonal-tiling density), so oversized non-triangle
  patterns fail fast with a TypeError instead of crashing or hanging deep
  in generation
- render options are validated with the same strictness: unknown keys and
  malformed values passed to toSVG()/toSVGTree() (includeNamespace,
  coordinateDecimals) and toCanvas() (scaling, applyCssScaling) throw a
  TypeError instead of silently emitting broken output (a NaN
  coordinateDecimals previously produced d='MNaN,NaN…' paths)
- pattern.toData() returns a fully independent copy (no shared structure
  with the live pattern), and Pattern.fromData() copies and validates its
  input — including opts.shape — before constructing a pattern
- polygon color values are lightweight { css() } objects, no longer chroma-js
  Color instances
- the chroma-js dependency is replaced by culori (bundled, tree-shaken —
  trianglify now has zero runtime dependencies and the browser bundle is
  ~18% smaller): custom colorFunctions receive plain (t) => color scale
  functions instead of chroma scales and return culori-style color objects
  (or a finished CSS string); trianglify.utils.mix returns a color object —
  serialize it with the new trianglify.utils.css
- patterns generated for a given seed differ from v4 (new RNG with separate
  seeded streams for geometry, palette selection, and color noise — changing
  color options can no longer change the geometry)

New features:
- shape option: regular polygons (pentagon, hexagon, heptagon, octagon),
  circles, and three exact pentagonal tilings (pentagon-cairo,
  pentagon-convex, pentagon-nonconvex) with closed-form geometry
  (docs/nonconvex-rosette-analysis.md); hexagons on the default grid layout
  form an exact gap-free honeycomb
- pointGeneration option: grid (default), poisson (Bridson), bestCandidate
  (Mitchell), spiral (Fermat/sunflower), and sphere layouts — every mode
  emits the same point count at a given cellSize, so modes are drop-in
  interchangeable
- Web Worker support: TrianglifyWorker client (accepts a script URL or a
  pre-constructed Worker) with AbortSignal cancellation, a prebuilt worker
  bundle exposed as the trianglify/worker export, and automatic serialization
  of built-in color functions (descriptor names and args are validated
  worker-side before resolving); trianglify.createWorkerHandler(post) builds
  a protocol-compatible message handler for hand-rolled worker scripts
- pattern serialization: pattern.toData() / Pattern.fromData(data) for JSON-
  and postMessage-safe caching and transfer; fromData structurally validates
  untrusted data
- new options: strokeColor, spiralDirection, spiralRatio; new built-in color
  functions radial() and angular()
- wide-gamut color output: colorOutput option ('rgb' default, 'oklch',
  'display-p3') controls how polygon colors are serialized; wide-gamut
  patterns render in SVG and browser canvas (toCanvas requests a display-p3
  canvas automatically), and toCanvas fails loudly in Node where node-canvas
  cannot parse CSS Color 4 strings; colorSpace gains 'oklab' and 'oklch'
  interpolation; colorOutput round-trips through toData()/fromData();
  out-of-gamut colors are gamut-mapped per CSS Color 4 (chroma reduction in
  oklch, preserving hue and lightness) instead of channel-clipped
- color pipeline performance: scale lookups are quantized and cached
  (colorQuantization option — 'auto' keys the step count to the output
  format's precision so the error stays below one output channel step;
  false disables), and tiling vertex dedup and shape gap-fill
  classification avoid per-probe string keys — pentagonal tilings generate
  ~2.8x faster, N-gon/circle shapes ~2x, default triangle patterns ~2x
- TypeScript throughout: bundled type definitions for ESM and CJS consumers,
  JSDoc on the public API surface, importable option/result types
- rendering improvements: re-rendering into an existing destSVG replaces its
  content instead of appending, SVG attribute values are escaped, the canvas
  antialiasing halo is suppressed when an explicit strokeColor is set (so
  canvas and SVG output agree), canvas is an optional peer dependency
  (browser/SVG-only usage installs nothing extra)
- TrianglifyWorker attaches its listeners with addEventListener, so message
  and error handlers installed on a caller-supplied Worker instance are no
  longer overwritten

Quality & tooling:
- exact-geometry certification tests for all tilings and the hexagon
  honeycomb, per-bundle output parity tests, real-pixel canvas and HiDPI
  tests, seeded fuzz and error-path tests, compile-time verification of the
  published type declarations, publint/arethetypeswrong packaging
  validation, and npm provenance publishing
- coverage enforces per-file floors alongside the aggregate thresholds, and
  the worker message protocol lives in workerHost.ts inside the main bundle
  so coverage measures it
- linting uses typescript-eslint's strictTypeChecked preset and the
  compiler enforces verbatimModuleSyntax
- CI runs a multi-OS, multi-Node matrix with SHA-pinned actions, CodeQL
  (security-extended queries), dependency review, and a recurring
  dependency audit; publishing verifies the release tag against the
  package.json version on both release and manual-dispatch triggers

v4
- ground-up port to ES2015
- support for node-canvas 2.6
- comprehensive test suite
- support for rendering wireframe patterns (no fill, just stroke)
- colorFunction has a new method signature that allows for more powerful customization
- new built-in colorFunctions: 'sparkle' and 'shadows'
- all-new example code, see examples directory
- all option keys are now camelCase, not snake_case
- antialiasing issues resolved for both SVG and Canvas rendering engines (#87, #30, #76)
- canvas rendering is now retina-ready by default
- removed dependency on seedrandom
- removed dependency on jsdom

v3
- close paths when rendering to canvas (thanks @Allidylls)
- bump a few dependencies for security
